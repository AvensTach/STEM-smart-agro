# SmartAgro 🌾

Система моніторингу мікроклімату та управління агро-датчиками.

## 🚀 Інструкція із запуску (Критерій E3)

Ця інструкція створена для швидкого розгортання та тестування системи з нуля. Проєкт використовує Docker для серверної частини та .NET 8 для клієнтської.

### 📋 Вимоги до системи (System Requirements)

Для успішного запуску на комп'ютері мають бути встановлені:

1. [Git](https://git-scm.com/downloads)
2. [Docker Desktop](https://www.docker.com/products/docker-desktop/) (або Docker Engine + Docker Compose)
3. [.NET 8.0 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/8.0)
4. **.NET MAUI Workload** (для запуску клієнтського застосунку). Якщо він не встановлений, виконайте в терміналі:

   ```bash
   dotnet workload install maui
   ```

### Крок 1: Клонування репозиторію

Відкрийте термінал (PowerShell, CMD або Bash) та виконайте:

```bash
git clone <посилання-на-ваш-репозиторій>
cd STEM-smart-agro
```

### Крок 2: Налаштування SSL сертифіката (Опціонально)

Щоб уникнути помилок HTTPS-з'єднання на етапі розробки, потрібно довірити локальний сертифікат .NET:

```bash
dotnet dev-certs https --trust
```
*(На Windows з'явиться спливаюче вікно з проханням підтвердити сертифікат — натисніть "Так").*

### Крок 3: Запуск Backend та IoT Worker (Docker)

Серверна частина та симулятор датчиків контейнеризовані. Щоб запустити їх, переконайтеся, що Docker увімкнений, і виконайте команду в кореневій папці проєкту:

```bash
docker-compose up --build -d
```

Очікуваний результат: Docker завантажить необхідні образи, збере проєкти та запустить 2 контейнери (Backend API та IoT Worker) у фоновому режимі. Воркер автоматично почне генерувати та відправляти телеметрію.
*Перевірити статус контейнерів можна командою `docker ps`.*

### Крок 4:Конфігурація середовища збірки (global.json)

Для забезпечення ідемпотентності збірки на різних комп'ютерах розробників використовується жорстка прив'язка до конкретної версії інструментарію. Наступна команда генерує маніфест global.json, який блокує використання експериментальних або мажорних оновлень (таких як .NET 9) під час розгортання:

```bash
dotnet new globaljson --sdk-version 8.0.100 --force
```

### Крок 5: Запуск Frontend (MAUI застосунок)

Після того, як бекенд успішно запустився в Docker, відкрийте **нове вікно терміналу** (або продовжуйте в поточному) та запустіть десктопний клієнт під Windows:

```bash
dotnet build SmartAgro.Frontend -t:Run -f net8.0-windows10.0.19041.0
```

Очікуваний результат: Відкриється вікно застосунку SmartAgro, де ви зможете авторизуватись та побачити показники мікроклімату, які генерує IoT Worker.

### 🧪 Запуск тестів (Критерій C1/C3)

## 🛠 Звітність по критеріях оцінювання

### C2: Обробка крайніх випадків (Edge Cases)

Детальний звіт по оброблених крайніх випадках знаходиться у файлі: `Edge_Cases_and_Exception_Handling_Report.md`.
Серед реалізованих кейсів:

1. Захист від блокування бази даних фоновим сервісом `DataArchiverService`.
2. Обробка помилок втрати зв'язку IoT-пристрою з бекендом (Fault Tolerance).
3. Валідація граничних значень (Boundary Values) на рівні моделей та контролерів.

### C4: Статичний аналіз коду (SonarCloud)

Детальний звіт знаходиться у файлі: `Criterion_C4_Report.md`.
Проєкт підключено до SonarCloud через GitHub Actions. Завдяки налаштуванням файлу `.editorconfig`, усі критичні та мажорні зауваження (Critical/Major) виправлені або оброблені, щільність помилок зведена до мінімуму.
